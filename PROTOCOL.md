# Study 40: Check flight-query fidelity before choosing trajectory compression

## Decision and acceptance

Can a small geometric error or a large point reduction hide an unacceptable change in a replay's route length or zone timing? Compare existing compression ideas on processed recorded aircraft tracks, then select a configuration using explicit development budgets before applying it to different aircraft. The audience is an engineer maintaining historical replay, visualization or analytical storage. The result is a bounded research benchmark and implementation exercise, not a flight-control tool or an observed airline-delay study.

Acceptance requires affirmative exact-source rights and unit identity; bounded capture with publisher checksum and private originals; independently reconciled cohort/split/exclusions before analysis; all declared candidates and failures retained; source and development dependencies committed before any final-track compression or query scores; separate independent native/numerical checks; meaningful fixtures and authored exercise cases; unchanged-original full-history replay under two recorded runtimes; three source-bound, inspected figures and a checked/rendered independent manuscript; privacy audit and exact candidate/main CI, matching tested/merged tree, remote annotated tag and synchronized program metadata. Do not average away a failed gate. Review at most three substantive rounds, 45 active review minutes and 60 review-specific calls per study; acquisition/execution is separate. Keep prior failures and report unknowns honestly.

## Eleven authored configurations

Retain identity (all points), uniform strides 2/4/8/16, geometric top-down Douglas–Peucker tolerances 10/25/50 metres, and time-synchronous top-down Douglas–Peucker tolerances 10/25/50 metres. All preserve first/last points. Stride sampling includes the final point even off-stride. The geometric method uses Euclidean point-to-finite-segment distance in three dimensions, clamping projection to endpoints. The synchronous method compares each reference point with the endpoint chord interpolated at that point's actual frame. For either top-down method, split at the earliest maximal-error interior point only when its error strictly exceeds the tolerance; otherwise keep the chord. Zero-length spatial chords use distance to the repeated endpoint. No stochastic seed, fitting, neural network, pretrained model or search extension is used. The tolerances/strides are authored small-grid examples, not regulatory limits or empirically optimal universal settings.

Decode all retained representations at every original frame by linear interpolation in time. There is no extrapolation. Endpoints and timestamps are unchanged. Compression does not automatically preserve the motion implied between spatially collinear points. The standard geometric and synchronous approaches are established prior work: [Douglas and Peucker, 1973](https://doi.org/10.3138/fm57-6770-u75u-7727), and [Meratnia and de By, 2004](https://doi.org/10.1007/978-3-540-24741-8_44). This is an applied fidelity audit, not a new simplifier, a global point-count optimum, or a comprehensive literature-priority claim.

Each encoded run has an eight-byte unsigned point-count header and one 32-byte little-endian record per retained point: signed int64 elapsed frame and three float64 metre coordinates. The identity representation uses the identical format. Record actual encoded lengths and independently verify 8+32*n bytes. This measures a declared point-record representation, not the original ZIP/CSV compression ratio, a database bill, network throughput or realized cost. Do not publish encoded coordinate payloads. Record candidate elapsed execution times privately for reproducibility bookkeeping; do not claim a portable speed benchmark.

## Queries, error budgets and selection

For every run/configuration retain all point-aligned errors: mean Euclidean position error (m), MSE of that norm (m²), RMSE (m), maximum(m), and coordinate signed bias (m). Retain the original/retained point counts and actual encoded-byte ratio. Route length is the sum of horizontal interpoint distances, in metres, on reference versus decoded original frames. Report signed and absolute route-length errors, and relative error where reference length is positive. For a stationary zero-length route the relative error is undefined; the selection guard requires decoded route length zero within the declared numerical tolerance, not an invented perfect percentage.

Two authored zones are horizontal closed disks of radius 1,000 m and 2,000 m around the source's runway-frame origin. Inside means x²+y²≤r². Occupancy seconds are the number of original one-second interval starts inside the disk, excluding the final sample; this is a sampled stepwise estimate, not a continuous exact boundary integral. The first transition is the earliest original frame whose membership differs from its initial membership; report its elapsed second or no-transition state. Compare that state and elapsed second after decoding. Preserve false/missed transitions and every signed/absolute occupancy and first-transition error. These are zone timing queries, not scheduled arrival delay, ATC separation, collision risk or validated operational decision labels.

Development admissibility requires every qualifying run to have maximum synchronous position error ≤ 25 m, absolute horizontal route-length relative error ≤ 1% (with the stationary rule above), absolute occupancy error ≤ 2 s for both zones, and identical first-transition state with absolute first-transition timing error ≤ 2 s when defined. Guards apply to individual runs; a macro average cannot hide a violation. Identity is the fallback and must pass. Among admissible configurations choose the smallest total actual encoded bytes on development; ties use this fixed order: identity, strides 2/4/8/16, geometric10/25/50, synchronous10/25/50. This total-byte objective serves storage, subject to query fidelity; it is not a tuned safety/financial cost function. If identity fails its sanity checks, stop the analysis.

Retain the complete development search table, each run/configuration result, gate failures, retained-index/split witnesses and execution status. For summaries first average run metrics within each aircraft, then average aircraft means equally within a partition. Also report maxima, denominators and all run-level exceptions. Use no p-values or independent-observation confidence intervals; runs share aircraft, day, airport, source preprocessing and scenarios. Identity, stride4 and geometric25 are predeclared readable reference comparisons regardless of which configuration wins. All final configurations are retained; there is no final search or undisclosed winner selection. A finite boundary winner is disclosed as such.
